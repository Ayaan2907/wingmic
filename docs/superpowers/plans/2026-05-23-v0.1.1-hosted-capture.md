## Goal

Ship the smallest version of capture+recall that, demoed in person to a builder friend, makes them say "wait, that's actually useful," in the next few hours. Without putting the entire extraction layer on Claude.

## Frame

Three PDFs of research (one main multi-level entity detection report, two Grok-flavored ones) all converge on the same shape: **hybrid LLM + traditional NER + graph + embeddings beats any single layer**. The current build is LLM-heavy: Web Speech → Claude/Vercel AI SDK `generateObject` with Zod → embeddings → in-memory cosine. The user wants to de-risk the Claude dependency and improve voice quality in real conversations.

The wedge for this session, three locked changes:

1. **AssemblyAI** as the ASR + first-pass entity-detection layer.
2. **Hybrid extractor** with Claude Haiku 4.5 demoted from "extractor" to "linker / action gate" — gated, not default.
3. **OpenRouter** as the unified LLM + embeddings provider. One key. `packages/extractor/src/models.ts` becomes the only place models are named.

Browser Web Speech is removed entirely — current implementation is broken and not worth maintaining. Text-paste is the universal fallback when audio capture fails.

## What the PDFs say (synthesized)

Three layers of recommendation, in order of impact for wingmic:

1. **ASR upgrade.** Web Speech is the weak link. Whisper local is fine for solo desk use; for real conversation in noisy environments use AssemblyAI / Deepgram / Gladia. They handle diarization, are robust to phone-call noise, and ship entity-detection as a side output.
2. **De-LLM the easy parts.** Embedding similarity + fuzzy name + a knowledge-graph-style canonical layer covers most entity resolution. Reserve LLM for ambiguous cases or relational reasoning the rules can't do (role↔company↔person linking, action intent classification).
3. **Recall upgrade.** Hybrid retrieval — vector top-k + keyword FTS + graph traversal — beats pure cosine. Add a small reranker. The PDFs called out libSQL `vector_top_k` specifically — already in your roadmap (#6).

Specific calls from Grok #2 (the roast):
- Voice accuracy is the visceral first-impression. Get it right or the demo fails before extraction matters.
- "Yet another CRM" framing risk. Lead with "post-meeting memo, automatic" not "personal CRM."
- Privacy tightrope: sending transcripts to APIs without explicit disclosure burns credibility with the developer crowd.

### Why this layout

- **Failsafe.** If AssemblyAI is down or out of credits, capture can fall back to Web Speech + Claude (existing path). Zero regression for current users.
- **Cheap on Claude.** Layer 3 only runs when needed, with a tighter scoped prompt. Easy to swap to a cheaper model (Haiku, Grok) later via LiteLLM-style adapter.
- **No schema churn.** Drizzle migrations, resolution code, recall router, eval fixtures all untouched.
- **Honest about what each layer does.** Voice accuracy is AssemblyAI's job; structured-data quality is shared between rules and LLM; resolution is graph code. Easy to debug — you can dump the layer-1/layer-2 output and see exactly what regex caught vs what AssemblyAI tagged.

### Step 3 — hybrid extractor + entity_detection at commit (90 min) — Task H4

Move AssemblyAI `entity_detection` call from the transcribe route into `tRPC capture.commit` (or a thin wrapper module called by it). This serves the trust-boundary fix (eng-review A1) — entities are always derived from the actually-committed transcript.

Create `packages/extractor/src/hybrid.ts`:

```ts
import { ExtractionResult } from './schema';
import type { AssemblyAIEntity } from './types';
import { extract as llmExtract } from './client';

interface HybridInput {
  transcript: string;
  providerEntities?: AssemblyAIEntity[];
}

export async function extractHybrid({ transcript, providerEntities }: HybridInput): Promise<ExtractionResult> {
  // Layer 1: AssemblyAI entities → ExtractionResult skeleton
  const skeleton = mapProviderEntities(providerEntities ?? []);
  // Layer 2: regex/heuristic fill for roles + actions + topics
  const filled = applyHeuristics(skeleton, transcript);
  // Layer 3: optional LLM gate
  if (needsLLMFallback(filled, transcript)) {
    const llm = await llmExtract(transcript); // existing path
    return mergeResults(filled, llm);          // prefer filled, fill gaps from llm
  }
  return filled;
}
```

Implement:
- `mapProviderEntities` — pure function, maps AssemblyAI's entity types (`person_name`, `organization`, `event`, `date`, `location`) into PersonCandidate / CompanyCandidate / EventCandidate. Unit-tested.
- `applyHeuristics` — pure function with three regexes:
  - role: `/\b(CEO|CTO|founder|engineer|developer|designer|PM|head of [\w ]+|lead [\w ]+) (?:at|of|@) ([A-Z][\w ]+)/i`
  - action: `/\b(send|email|remind|todo|intro|message|follow up|ping|check in|call|meet) \b/i` → ActionCandidate
  - topic: noun-phrases via tiny dependency `compromise` OR keep it dumb (split on commas/dashes near person mentions)
- `needsLLMFallback` — boolean predicate. Returns true if persons.length > 0 AND any role==null, OR actions.length==0 AND transcript matches imperative-verb regex.
- `mergeResults` — prefer heuristic over LLM where they conflict; fill nulls from LLM.

Wire into `packages/extractor/src/index.ts` as an additional export (`extractHybrid`). Keep `extract` (LLM-only path) intact.

In `apps/app/lib/trpc/routers/capture.ts`, accept an optional `providerEntities` input on `commit`. If present, route to `extractHybrid`; else fall back to `extract` (existing).

### Recall page — one change

Drop the per-card percentage. Replace with a relevance band sticker:

- `strong match` (accent pill) for cosine ≥ 0.7
- `loose match` (muted accent) for 0.5 ≤ cosine < 0.7
- `weak match` (text-40 mono) for cosine < 0.5

Reasoning: `76%` reads as "AI is unsure about this person being real" — wrong mental model. Sticker bands read as a system claim about query-match relevance, not entity-confidence. Raw score kept available via `data-score` attribute for tuning.

Secondary: empty-state copy needs a fork — `recall.data.entities.length === 0` AND user has zero entities total ≠ "you've captured people but none match this query." Two empty states:
- Cold (no captures yet): `nothing here yet. capture someone first →` (linked to `/capture`)
- Has captures, no match: `no matches yet. try a broader query.`

### Capture header nav

### Onboarding decision

**Trust the user. No scripted first-capture moment.** The audience is 1–3 builder friends in person with the user present demoing. A "try saying: I just met Sarah..." coach mark reads as training wheels to that crowd. The existing hero copy + placeholder transcript shape already demonstrates a good memo without labeling it as guidance.

The only place a user can land cold without the demoer present.

## UI/UX Specification v2 — Chat-thread + Push-to-talk (2026-05-23, locked)

User direction (2026-05-23): the primary page is a **chat thread** with a **hold-and-speak** button. Sent memos appear as bubbles with inline graph cards. Follow-up replies link to parent interactions. Nav surfaces: History, Recall (entity browser with clusters), Settings. This spec supersedes UI/UX Specification v1 above.

Consolidated output from two parallel subagent reviews (UI Designer + UX Architect). Both agents independently recommended bottom tab nav, a 24h-retention audio model, and a long-press reply pattern.

### 1. Architecture risk + mitigation

The chat-thread metaphor implies turn-taking continuity that the data model doesn't have. Five memos about five different people are five disjoint graph commits, not a conversation. **Mitigation:** treat the thread as a log view of recent commits — group strictly by time (Today / Yesterday / This week / Earlier), not by topic. The graph card under each bubble is the actionable artifact; the bubble is just the receipt. No "AI assistant" reply bubbles — the system response is the quiet graph card, never a persona.

### 2. Data model deltas (Drizzle schema changes — required before chat-thread can ship)

```
interactions
  + parentInteractionId   text   nullable   FK→interactions.id
  + threadRootId          text   nullable   FK→interactions.id   -- denorm: reply-chain root
  + audioStorageKey       text   nullable   -- R2/S3 key if retained, null otherwise
  + audioRetentionExpiry  integer (timestamp) nullable           -- TTL for auto-purge
  + clientCaptureId       text   not null                        -- uuidv4, idempotency anchor
  + status                text   not null   default 'committed'  -- pre-commit state lives client-side
  + index (userId, capturedAt desc)
  + index (parentInteractionId)
  + unique (userId, clientCaptureId)                              -- prevents double-commit on retry

users (settings additions)
  + audioRetentionMode    text   not null default '24h'   -- 'none' | '24h' | '7d' | '30d'
  + linkerModelOverride   text   nullable
  + preferredMicDeviceId  text   nullable
  + asrLanguage           text   not null default 'en-US'
  + acknowledgedPrivacy   integer (boolean) not null default 0    -- gates first-visit modal
```

No new tables. Threads are derived views, not stored. `clientCaptureId` is the idempotency key — generated client-side at `pointerup`, server uses `(userId, clientCaptureId)` as a unique constraint. This makes optimistic UI + retries safe.

### 3. Resolution algorithm — replyTo bias

Pseudocode for the modification to `packages/extractor/src/resolution.ts:resolvePerson`:

```
baseScore = 0.55 * nameMax + 0.25 * embeddingScore + 0.20 * companyBoost

if replyContext (commit was called with parent interactionId):
  parentEntityIds = entities linked to parent interaction
  replyBoost = (entity.id ∈ parentEntityIds) ? (0.15 * nameMax) : 0
  acceptThreshold = 0.78                  // lower when reply context is strong
else:
  replyBoost = 0
  acceptThreshold = 0.85                  // unchanged

score = baseScore + replyBoost
if best.score >= acceptThreshold: match
else: create new
```

The boost is additive on top of name strength — never standalone. Prevents reply chains from accidentally collapsing two different people with the same first name.

### Hold-to-talk button — visual + interaction spec

| State | Size | Fill | Label | Trigger |
|---|---|---|---|---|
| Idle | 88px circle | accent #FFC452 | `HOLD TO TALK` mono 10px below | — |
| Hold-active | 112px (180ms ease-out) | accent + 0 0 32px accent50 glow | `RELEASE TO SEND · ← DISCARD · ↑ LOCK` | `pointerdown` |
| Slide-up-armed (40-80px above origin) | 112px | accent | `◇` lock glyph appears 80px above, grows to 18px | `pointermove` dy < -40px |
| Locked (slide >80px up, then release) | 88px square coral | `#FF6B6B` w/ ■ glyph | `◇ LOCKED` sticker badge floats above | `pointerup` after dy < -80px |
| Slide-left-armed (40-80px left) | 112px | shifts toward coral | `← DISCARD` coral pill appears 80px left | `pointermove` dx < -40px |
| Discard-committed (dx < -80px OR release outside) | shrinks to 0 | — | — | threshold cross |

**Slide thresholds:** 40px = arm (visual hint), 80px = commit (haptic + state change). Hysteresis: once locked, slide thresholds disengage.

**Haptic hooks** (`navigator.vibrate`, no-op where unsupported):
- Hold start: `vibrate(8)`
- Threshold cross: `vibrate(10)`
- Lock engaged: `vibrate([15,40,15])`
- Discard committed: `vibrate([30,20,30])`
- Send (in-bounds release): `vibrate(12)`

**Accessibility fallback:** tap-and-tap mode. Tap → starts recording (jumps to LOCKED immediately), tap stop pill → ends. Mono caption explains both: `HOLD or TAP`. Non-negotiable — primary action must work without sustained press for users with motor disabilities.

Each pill: 32px circular avatar monogram (color = Layer-source: AssemblyAI=mint #86efac / heuristic=accent #FFC452 / Haiku=info-blue #7DD3FC), name 14px 700, role+company subtitle 12px text-55. ### 13. Optimistic UI race-condition handling (commit serialization)

Both subagents flagged a concrete failure: two memos about Sarah sent 200ms apart both see `userEntities` without the other's insert → both create new entities → duplicate.

**Mitigation:** server-side per-user lock on the `commit()` resolution step. Mechanism:
- Add a `userCaptureLocks` table or a `users.captureLockGeneration` integer
- `commit()` opens a transaction, increments the generation, reads entities + writes new entity + closes transaction
- libSQL doesn't support `SELECT ... FOR UPDATE`, so emulate via `UPDATE users SET captureLockGeneration = captureLockGeneration + 1 WHERE id = ?` at the start of the transaction (forces serialization on the user row)

Cost: one extra write per commit. Prevents the duplicate-entity race.

**Concurrent captures from one user:** UI shows multiple bubbles simultaneously, each in its own progressive state. Network-layer parallel uploads OK. Resolution-layer serialized server-side.

**Reply chains:** a reply to a bubble that hasn't reached `committed` yet queues client-side. Reply's commit fires only when parent's `interactionId` is known. No phantom replies in flight.

### 14. Audio retention call

**Default: 24-hour retention, opt-out to `none`, opt-in to `7d`/`30d` in Settings.**

Reasoning:
- Without retained audio, the re-listen affordance is theater — users tap play, find nothing past current session, lose trust.
- Without retained audio, retry-after-network-failure becomes "re-record." Brutal on mobile.
- 24h covers "I want to re-listen this afternoon" at ~$0.02/user/month at R2 pricing for active users.
- Privacy: 24h auto-purge limits blast radius for the most sensitive artifact (voice identity).
- Disclosure already says "audio goes to assemblyai." Adding "and we keep it 24h so you can re-listen" is honest and small.

Implementation: AssemblyAI uploads via our route → stream to R2 keyed by `userId/clientCaptureId` → AssemblyAI fetches from signed URL (or proxy). Background worker purges expired keys daily.

### 16. Pushback on chat-thread metaphor (worth noting, not blocking)

Three concerns the user should be aware of:

1. **Reply usage could re-engage "talk to AI" expectations.** If reply usage crosses 15% of memos, users may start asking the system things ("which one was Sarah?") and discover the thread isn't conversational. Either keep reply behind long-press only (no default affordance), OR add a "ask in this thread" command in v0.2 that is a recall query scoped to local thread context. Instrument reply rate to know if this becomes a problem.
2. **Visualize reply chains explicitly** with a 1px accent left-border connecting parent → child bubble. Makes the relational claim visible.
3. **Alternative model worth knowing:** "daybook" (one swipeable card per day, no infinite scroll). Same component vocabulary. Sidesteps the conversation-metaphor trap and matches data clustering (by capture time). NOT recommended for v0.1.1 — chat-thread is 90% the same parts and reply-to is genuinely useful. But if reply rate climbs, daybook is the conversion target for v0.2.

### 17.2 Delete cascade rule

The graph is append-only. Soft-deletes never cascade to entities. Schema deltas:

```
interactions
  + deletedAt              integer (timestamp)  nullable

entities
  + deletedAt              integer (timestamp)  nullable

interactionEntities, entityCompanies, entityEvents, entityTopics, entityFacts
  + sourceDeleted          integer (boolean)    not null default 0
```

**Memo soft-delete (interactions.deletedAt set):**
- Join rows (`interactionEntities`, derived `entityFacts` with `sourceInteractionId = thisMemo`) are preserved but flagged `sourceDeleted = 1`.
- Entities themselves are NEVER touched by a memo deletion.
- Entity page may render flagged facts dimmed with mono caption `from a deleted memo` text-40.

**Entity soft-delete (entities.deletedAt set):**
- All edges to that entity (`interactionEntities`, `entityCompanies`, `entityEvents`, `entityTopics`, `entityFacts` where this entity is on either side) are flagged `sourceDeleted = 1`.
- Future captures cannot resolve to this entity — `resolvePerson` filters `WHERE deletedAt IS NULL` when building `userEntities`.
- Recall / cluster pages filter the same way. History bubbles still show the entity name (read-only audit log), but the pill no longer links.

**Undo window:** 30 seconds. Tombstone chip slides in at thread bottom (or page top on entity page): `*${name}* removed · ↶ undo` mono 12px on coral-tinted surface. `↶ undo` clears the `deletedAt` and unflags affected joins. After 30s the chip dismisses and the delete persists; no hard-delete sweep in v0.1.1 (TTL purge deferred to v0.1.2).

**Hard delete** (Settings → "delete all my data"): wipes the user's row + cascade-deletes everything via FK. Separate path, not affected by these soft-delete rules.

### 17.4 Accessibility minimum bar

Floor, not ceiling. Every interactive element meets this; new components are reviewed against it before merge.

| Concern | Rule |
|---|---|

| Tab bar semantics | `<nav aria-label="primary">` wraps the bar. Tabs are `<button>` with `aria-current="page"` on the active one. |
| Hold-to-talk button | `aria-label="Hold to record voice memo. Tap to use lock mode."` · `aria-pressed` toggles while held · `aria-keyshortcuts="Space"` on desktop. |
| Level meter | `role="status" aria-live="polite"` wrapping the live duration counter. The 22 bars carry `aria-hidden="true"` — decorative. |
| Icon-only controls | `×` discard, `⋯` kebab, `▶` playback, `■` stop, `↻` retry, `↪` reply — each gets a descriptive `aria-label`. |
| Keyboard reachability | Every interactive element reachable via `Tab` in DOM order. Bubbles in the thread are `tabindex="0"`; `Enter` on a focused bubble opens the long-press action sheet (touch long-press = keyboard `Enter`). |

```

button hold-expand 88→112px      → instant size change
discard slide-shrink             → instant dismiss
```

Recording, transcribing, and commit functionality MUST NOT depend on motion. Anything the user must perceive is also conveyed through text or a static state. Color contrast already meets WCAG AA per `design/design-system.md`.

### 17.5 Empty graph card spec

When the hybrid extractor returns zero persons, zero companies, zero events, and zero actions (silent audio, filler-only speech, "uh I forgot what I was saying"), the bubble must look intentional, not broken.

**Bubble shape:**
- Transcript bubble renders normally (top, surface-2, transcript text, audio replay chip, kebab).
- Graph card section reduces to **one row: footer only**. No People row, no Companies row, no Follow-ups, no Notes-collapsible.
- Footer mono 10px text-40, single line: `no entities found · ${transcribeMs}s transcribe · ${commitMs}s commit`.
- No headline framing like `graph updated` or `nothing to link` — silence is the right tone.

**Long-press still works** — edit, copy, delete, reply are all available. If the user taps `edit` and adds a name ("oh right, *sarah* was the one talking about rust"), the save flow re-runs `entity_detection` + hybrid extraction on the new transcript and the bubble updates with a proper graph card on next render. No new bubble, same `clientCaptureId`.

**Why no error-state framing:** zero-entity is a valid outcome of a real capture, not a failure. The transcript is preserved, the audio is preserved, the user can edit. Treating it as an error would punish users for thinking out loud.
