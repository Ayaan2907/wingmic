# PR θ-search — /search cluster browser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Checkbox steps.

**Goal:** Promote recall from a back-door route to a first-class `/search` cluster browser, reading `?q=` so the ⌘K palette and chat link stop pointing at a dead destination.

**Architecture:** New `/search` route + `SearchClient` reuses the existing `recall.query` tRPC (no new backend). Reads `?q=` from the URL (closing the dropped-intent gap), renders results with a segmented control (by-company / by-event / by-topic / recent) over the same result set. `/recall` becomes a redirect to `/search`. The chat link and ⌘K already target `/search?q=` (⌘K shipped in λ-shell; chat link updated here). Mounts inside the AppShell — no per-screen nav.

**Tech Stack:** Next.js 15 App Router, tRPC v11, Vitest. Branch: `feat/v0.1.2-pr-theta-search` (stacked on `feat/v0.1.2-pr-iota-graph` — linear stack, shares the middleware edits).

**Reuse:** Read `apps/app/app/recall/RecallClient.tsx` first — it already calls `trpc.recall.query.useQuery({ q, limit })` and renders the result cards with score-threshold coloring (>0.7 / >0.5). Reuse that result-card rendering and the query wiring; the new part is (a) seeding `q` from `?q=` via `useSearchParams`, and (b) the segmented control.

**Result shape** (from `recall.query`): `{ entities: Array<{ id, name, ...company/event/topic edges, score }>, durationMs }`. Read the tail of `apps/app/lib/trpc/routers/recall.ts` for the exact entity fields (company/event/topic arrays per entity) before writing the grouping.

**Segmented control:** `by-company | by-event | by-topic | recent`. Default `recent` (the raw ranked order). The other three group the SAME returned entities by their joined company/event/topic edges (an entity with no edge of that kind falls into an "unsorted" bucket). This is client-side reorganization of one result set — no new query.
