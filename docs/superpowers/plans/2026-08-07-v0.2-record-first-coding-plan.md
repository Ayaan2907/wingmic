## 0 · Product north star (one paragraph)

After sign-in, the user should feel **one verb**: record. Tap → speak → done → **immediately ready to record again**. Extraction and graph writes happen **in the background**. Home keeps its **acts draft queue** — those cards are real product UI and must be wired to extracted follow-ups (email, calendar invite, reminder, intro), not removed. Imports cold-start people so spoken names resolve to real contacts. Companies/events stay Framing D canonical. **Ship order: data truth → record-first UX → wire acts drafts → imports → enrichment** — one PR per WP.

## 1 · UX expert pass — simplify the feel

### 1.1 What confuses today
- Home **acts drafts are intentional UI** (the Acts surface) — but CTAs are still disabled / seeded, so they feel broken rather than unfinished.
- Jargon (`commits`, `edges`) without a clear first verb (“tap to talk”).
- Person pages forget the memo that created them (`source_interaction_id` null) — T1 fixes new commits.
- Desktop rails show mock people next to real data.
- Next recording can feel gated by pipeline state / route churn.

### 1.2 Target feel (acceptance, not mock pixels)
1. **Post-login destination = `/chat` with mic ready** (home stays as glance + **working** acts queue). Onboarding still gates once; after acknowledge → chat (or home if user prefers — Q1).
2. **Record loop:** stop → orb returns to idle **immediately** → user can start again while prior bubbles show `transcribing → linking → committed` in the thread.
3. **Background is the product:** no modal “please wait to record again”; failures stay on that bubble with retry/paste.
4. **Home acts drafts stay — and become real.** Same `ActCard` chrome on home + `/acts`. Data comes from extracted memo actions (email / meeting / reminder / intro / todo), not hardcoded Sarah/Marcus seeds. Empty only when the user truly has no pending acts.
5. **One teaching beat:** first session shows “tap to talk” on the orb once; then silence.

### 1.3 Coding WPs — UX (do after T1 so person pages tell the truth)

| WP | Change | Files (exact) | Tests |
|---|---|---|---|
| **U1** | Post-onboarding / sign-in default → `/chat` (callbackURL + home redirect if onboarded) | `SignInClient.tsx`, `onboarding` success path, `app/page.tsx` gate | existing onboarding/signin tests + one redirect assert |

**Do not** rename brand jargon (`commit`) in this phase — teach via empty states / hint, not a glossary rewrite.

**Storage decision (coding-locked, Framing D):**
- **People contacts:** store **your** copy as private `entity` rows (+ facts). Do **not** scrape full social graphs into a global people table.
- **Public profile fields** (company domain, LinkedIn URL): store as facts on **your** entity; company row stays canonical shared.
- **Map vs store:** store enough to resolve offline (name, email, urls). Enrich later by URL fetch only where ToS allows; never commit scraped bios into other users’ graphs.
