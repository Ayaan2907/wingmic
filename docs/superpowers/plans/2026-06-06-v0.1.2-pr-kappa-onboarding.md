# PR κ-onboarding — First-run onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Checkbox steps.

**Goal:** Add a 3-step first-run `/onboarding` flow, gated by `users.acknowledgedPrivacy` — a real gate (not theater): an un-acknowledged user landing on home is redirected into onboarding, and finishing/skip flips the flag.

**Architecture:** The gate is **server-side** (middleware is cookie-only and can't read the db). A shared `requireOnboarded(userId)` helper reads `users.acknowledgedPrivacy` and `redirect('/onboarding')` when false; it's called from the home server page (the primary post-signin landing). `onboarding.acknowledge` mutation flips the flag (userId-scoped). `/onboarding` is exempt from the gate (it must not call `requireOnboarded`) or it loops. Mounts inside AppShell-less chrome (onboarding is in the shell's CHROMELESS list — already added in λ-shell).

**Tech Stack:** Next.js 15 App Router, tRPC v11, Drizzle + libSQL, Vitest. Branch: `feat/v0.1.2-pr-kappa-onboarding` (stacked on `feat/v0.1.2-pr-eta-settings`).

- [ ] **Step 4: Implement the gate helper**

Create `apps/app/lib/onboarding-guard.ts`:
```ts
import { redirect } from 'next/navigation';
import { db, schema } from '@wingmic/db';
import { eq } from 'drizzle-orm';

/** Server-only first-run gate. Redirects to /onboarding when the user has not
 *  acknowledged privacy. Call from authed server pages AFTER the session check.
 *  Do NOT call from /onboarding itself (would loop). */
export async function requireOnboarded(userId: string): Promise<void> {
  const user = await db.query.users.findFirst({ where: eq(schema.users.id, userId) });
  if (user && !user.acknowledgedPrivacy) redirect('/onboarding');
}
```
